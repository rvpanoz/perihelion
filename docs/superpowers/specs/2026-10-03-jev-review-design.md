# Jev PR review: design

Date: 2026-10-03. Status: approved in conversation, awaiting written-spec review.

## Goal

A dev-only GitHub check that guards non-negotiable #3 ("fixtures are ground truth; never loosen tolerances") and the
commit/PR message rules in CLAUDE.md. It uses TypeSafe's Jev model for the semantic judgements that plain code
cannot make, and plain code for everything else.

## Constraints

- **No AI at runtime (#1).** The tool lives in its own workspace and is never imported by `apps/*` or `packages/*`.
- **Tests never touch the network (#2).** `npm run check` covers the tool with unit tests and recorded Jev responses;
  only the separate workflow calls Jev.
- **Recordings are ground truth (#3).** Recorded Jev responses are regenerated by a script, never edited by hand.
- **No secrets in the repo (#6).** `TYPESAFE_API_KEY` comes from the environment (`.env` locally, a repository secret
  in Actions). The user sets the secret; the agent never handles its value.
- **No new third-party packages.** Plain `fetch` (Node 24) + `zod`; `tsx` and `@types/node` are already in the
  lockfile at the same versions.
- Jev 1.13 is weak at arithmetic, counting, date comparison and literal reading
  (<https://docs.typesafe.ai/model-jaggedness/jev-1.13>). Jev never compares numbers here; it only classifies them.

## Decisions (user)

1. Integrate ideas 1 (fixture and tolerance guard) and 2 (commit/PR message check); not issue labelling.
2. Plain `fetch` + zod, no SDK.
3. Fixture changes clear with an approval label that only the user applies.
4. A loosened tolerance blocks; message findings only advise.
5. If Jev is unreachable and changed test numbers exist, the tolerance check fails closed.
6. Approach A: a new `tools/review` workspace (`@perihelion/review`).
7. A throwaway demo PR may hand-edit one fixture byte to verify the block and the label.

## Architecture

```
tools/review/
  package.json                @perihelion/review; scripts: typecheck, test, review, record
  tsconfig.json               extends ../../tsconfig.base.json
  vitest.config.ts
  examples/                   labelled example set (committed, reviewed by the user before recording)
  src/
    typesafe/jevClient.ts     POST https://api.typesafe.ai/v1/systemone, model jev-latest
    diff/parseDiff.ts         unified diff text → files + changed line pairs
    groundTruth/
      fixtureFiles.ts         protected paths changed?
      numberChanges.ts        numbers that changed between paired test lines
      toleranceKind.ts        Jev Choice: what kind of number is it?
      loosening.ts            kind + old/new → looser / tighter / equal
    messages/
      trailers.ts             git-trailer lines in commit messages
      messageJudgements.ts    Jev Nouls on commit messages and the PR body
    report.ts                 findings → Markdown
    main.ts                   GitHub event → checks → comment, summary, exit code
    recorded/                 recorded Jev responses (generated)
.github/workflows/review.yml
```

Root changes: add `tools/*` to `workspaces` in `package.json` and to `projects` in `vitest.config.ts`. CLAUDE.md's
Layout section gains one line for `tools/review` (needs user approval when the edit is made).

### Jev client (`jevClient.ts`)

- `askJev(request, options)` returns `{ ok: true, answers, usage } | { ok: false, reason }`; network and HTTP errors
  are caught in one place and never thrown to callers.
- The response is validated with zod (Noul, Choice and Score answer shapes from <https://docs.typesafe.ai/api>).
- Retries 429 and 529 with exponential backoff (3 attempts). Per-attempt timeout through `AbortController` +
  `setTimeout`, not `AbortSignal.timeout`, so fake timers drive it in tests.
- `fetch` and the key are injectable; a missing key returns `{ ok: false, reason: 'missing-key' }` without a request.

### Fixture and recording guard (`fixtureFiles.ts`, no Jev)

Protected paths: `packages/fixtures/data/**`, `packages/fixtures/upstream/**`, `packages/fixtures/src/recorded/**`,
`tools/review/src/recorded/**`. Any added, modified, deleted or renamed file there is a blocking finding.
`apps/web/public/snapshot/**` is not protected: `npm run snapshot` refreshes it as routine data.

### Tolerance guard

1. **`numberChanges.ts` (code).** For files matching `*.test.ts` / `*.test.tsx`, pair each hunk's removed and added
   lines in order. For each pair, tokenise numeric literals (integers, decimals, exponents, `_` separators, leading
   `-`). If both lines have the same token count and the non-numeric text is identical, each differing number is a
   candidate. Pairs that differ in other text, and unpaired added or removed lines, are not candidates (out of scope).
2. **`toleranceKind.ts` (Jev).** One request for all candidates (questions are independent and run in parallel).
   State per candidate: file path, old line, new line, three lines of context above and below, and the old and new
   value of the one number being asked about. One Choice per candidate:
   - `upper-bound`: a maximum allowed error or upper limit on a measured quantity (bigger is looser)
   - `closeness-digits`: the precision argument of `toBeCloseTo` (fewer digits is looser)
   - `margin-multiplier`: a factor applied to a measured error to get the allowed error (bigger is looser)
   - `lower-bound`: a minimum required value in a `toBeGreaterThan` style check (smaller is looser)
   - `not-a-tolerance`: an expected value, input, count, index or anything else
3. **`loosening.ts` (code).** Compares old and new values for the chosen kind and returns looser, tighter or equal.
4. **Gating (code).** A candidate blocks when the kind is a tolerance kind and the change is looser, or when the
   answer is `not-a-tolerance` with confidence below the cutoff (fail closed). The cutoff is measured, not guessed
   (see Testing). If Jev is unavailable, every candidate blocks.

### Message check (advises only)

- **Trailers (code):** a final paragraph of `Token: value` lines in git-trailer form (`Co-Authored-By:`,
  `Signed-off-by:` and similar) in any PR commit.
- **Commit messages (Jev):** two Nouls per commit: "describes only the functional change to the code, with no
  process, review, tooling or attribution talk" and "written in plain English".
- **PR body (Jev):** one Noul, "written in plain English". Verification notes and tables are allowed in PR bodies.
- **PR body (code):** contains `Closes #N`.
- A Noul below 0.5 is reported. Message findings never change the exit code.

### Workflow and reporting

- `.github/workflows/review.yml` on `pull_request` (`opened`, `synchronize`, `reopened`, `edited`, `labeled`,
  `unlabeled`); never on `push`. Checkout with `fetch-depth: 0`, `setup-node` from `.nvmrc`, `npm ci`,
  `npm run review --workspace @perihelion/review`.
- Permissions: `contents: read`, `pull-requests: write`. Env: `TYPESAFE_API_KEY` (secret), `GH_TOKEN`.
- `ci.yml` is unchanged.
- The label `ground-truth:approved` clears every blocking finding; the comment still lists what was approved. The
  agent creates the label but never applies it.
- One PR comment, found by the marker `<!-- perihelion-review -->` and updated in place. Each finding shows file and
  line, old and new value, Jev's answer and confidence, and whether it blocks or advises. The same Markdown goes to
  `$GITHUB_STEP_SUMMARY`.
- Exit code 1 only when a blocking finding remains after the label.

## Testing

- **Unit tests** (in `npm run check`): `parseDiff` and `numberChanges` on committed diff text (renames, CRLF, several
  numbers per line, `1e-12` and `1_000`); `fixtureFiles` path rules; `loosening` as a kind × direction table;
  `trailers`; `report`; `main`'s decision logic (label, fail closed, advice never fails).
- **Client tests:** injected `fetch`; malformed responses rejected; 429/529 retry and give-up; timeout; missing key.
- **Recorded responses:** `npm run record --workspace @perihelion/review` (dev only, network) sends the example set
  to Jev and writes `src/recorded/*.json`; tests replay them.
- **Example set** (`examples/`, labels reviewed by the user before recording):
  - Tolerances: about 30 real changed-number pairs sampled from git history (all `not-a-tolerance`; history has no
    tolerance edits) and about 25 synthetic edits of real tolerance lines (each kind loosened and tightened, plus a
    line holding both a tolerance and an expected value).
  - Messages: about 15 real commit messages (pass) and about 15 synthetic bad ones (review talk, WIP, "make tests
    pass", an attribution trailer, non-English, "as discussed").
- **Cutoff:** the lowest confidence cutoff that blocks every loosened example, with its false-positive count, recorded
  as a decision in `PROGRESS.md`. A test asserts that on the recordings every loosened example blocks and no
  tightened example does. If Jev cannot separate the kinds, stop and report the confusion table.
- **End to end:** the real PR runs the workflow on itself (it adds `tools/review/src/recorded/**`, so it blocks until
  the user applies the label, which is expected); then a draft demo PR (closed, never merged) with one
  hand-edited fixture byte and one loosened `toBeCloseTo` digit must block, clear with the label, and update its
  comment in place.

## Out of scope

Loose tolerances in newly added tests, changed expected values, issue labelling, checks on `push` or `main`, and any
use of Jev in `apps/*` or `packages/*`.
