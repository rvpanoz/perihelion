# Contributing

Thanks for looking. Bug reports and ideas are welcome as [issues](https://github.com/rvpanoz/perihelion/issues).
Before a pull request, read the rules below: the tests and the review check enforce most of them.

## Non-negotiables

1. **No AI at runtime.** No LLM/AI API calls anywhere in shipped code. (`tools/review` is a dev-only PR check and is
   never imported by `apps/*` or `packages/*`.)
2. **Tests never touch the network.** They use committed fixtures and recorded responses.
3. **Fixtures are ground truth.** Never edit fixtures or recordings by hand, and never loosen a tolerance to make a
   test pass: fix the code. Fixtures and recordings are regenerated by their scripts (`npm run fixtures`,
   `npm run stars`, `npm run record`). A pull request that changes them, or loosens a tolerance, is blocked until the
   maintainer approves it. See [`docs/accuracy.md`](docs/accuracy.md) for every tolerance and where it comes from.
4. **`packages/orbit` has zero runtime dependencies** and no DOM or Node APIs. It is pure functions over numbers.
5. **The web app never calls NASA/JPL directly.** All data goes through `apps/server`, with a bundled snapshot as
   the fallback.
6. **Never commit secrets.** Credentials come from the environment only. Every upstream the app uses is keyless.

## Facts and illustrations

Values shown to the user as facts (distances, speeds, dates, sizes) come from JPL or DONKI, never from the engine's
approximations: a unit conversion of the source's figure is fine, a value re-derived from the engine is not.
Anything illustrative (the aurora, the magnetosphere, the close-up schematic) is labelled as such in the UI.

## Engine conventions (`packages/orbit`)

- Units in names: `distAu`, `velAuPerDay`, `jdTdb`, `angleRad`. Radians internally; degrees only at I/O boundaries.
- Frame: heliocentric ecliptic J2000 unless a name says otherwise.
- Time: Julian Date (TDB) internally; convert from UTC at the boundary.
- Functions are pure and allocation-light; hot paths accept an optional `out` array.
- Every public function has a unit or property test. Astronomy maths cites its formula or source in a comment.

## Rendering conventions (`apps/web`)

- Per-frame animation never goes through React state: use `useFrame` and refs.
- Camera-relative rendering and a logarithmic depth buffer are always on. World unit = 1 AU.
- Planets, the camera and the focused object are positioned on the CPU in float64; only the swarm moves on the GPU.
- One time source (the time controller store); every scene element reads from it.
- Shaders live next to their component as `.glsl` files, with typed uniforms.
- After a visual change, check frame times: the target is 60 fps on a mid-range laptop.

## Upstream data

- Every upstream response is validated with zod and treated as untrusted.
- Not used, on purpose: the Mars Rover Photos API (offline), InSight weather (frozen 2020 data) and the legacy APOD
  API (archived).

## Code style

- TypeScript strict, ESM, no `any` (use `unknown` and narrow it).
- Small functions with intention-revealing names; comments explain _why_, not what.
- Match the surrounding code.

## Pull requests

- Branch off `main` (`phase-N/<short-name>` or a descriptive name) and keep each PR to one change.
- `npm run check` (typecheck, lint, test, build) must pass.
- Commit messages and PR descriptions describe the change in plain English: no process talk and no trailers.
- A PR that fixes an issue says `Closes #N` in its description.
